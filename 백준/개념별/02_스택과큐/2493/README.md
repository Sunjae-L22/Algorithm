# BOJ 2493 · 탑

[문제 원문](https://acmicpc.net/problem/2493) · [제출한 Python 풀이](solution.py)

## 문제를 내 말로

높이가 서로 다른 탑이 최대 50만 개 있다. 각 탑에서 왼쪽으로 보낸 신호를 처음 받는 탑의 번호를 구한다. 번호는 1부터 시작하고, 수신 탑이 없으면 0이다.

## 접근과 정당성

처음에는 각 탑에서 왼쪽을 훑었다. 오른쪽부터 읽는 방향은 그대로 두고, 아직 수신 탑을 찾지 못한 인덱스를 `waiting_top`에 모았다. 스택에 남은 탑은 바닥에서 꼭대기로 갈수록 낮아진다.

예를 들어 높이가 `8 3 5 7`이면 오른쪽부터 7, 5, 3이 차례로 기다린다. 높이 8을 만났을 때 맨 위의 3부터 5, 7까지 꺼내 세 답에 모두 1번을 적는다. 각 탑이 이때까지 남아 있었다는 건 그 탑과 8 사이에 신호를 받을 만큼 높은 탑이 없었다는 뜻이다.

일반적으로 현재 탑보다 낮은 꼭대기 인덱스 j를 꺼내면 현재 탑이 j의 가장 가까운 수신 탑이다. 꼭대기가 현재 탑보다 높아지면 그 아래도 더 높으므로 멈춘다. 현재 인덱스를 넣으면 높이 순서가 유지된다. 순회가 끝날 때까지 남은 탑은 답의 초기값 0을 유지한다.

## 경계 입력과 검증

공식 예제 1개와 자체 경계 입력 4개로 확인했다. 탑 하나, 오름차순, 내림차순, 한 탑이 연속으로 여러 답을 확정하는 경우를 포함한다. 백준 AC는 현재 코드로 제출한 사용자가 확인했다.

## 시간·공간 복잡도

각 인덱스를 한 번 넣고 최대 한 번 꺼낸다. 모든 while 반복에서 성공한 pop은 총 N번 이하이고, 각 바깥 반복의 마지막 조건 검사도 한 번뿐이다. 전체 시간 O(N), 답 배열과 스택을 포함한 추가 공간 O(N)이다.

## 다음에 기억할 것

`for top in waiting_top` 도중 `popleft()`하면 순회 중인 deque의 크기가 바뀌어 예외가 난다. 이 풀이에서 검사할 곳은 가장 최근에 넣은 오른쪽 끝이다. `while`로 끝을 확인하고 같은 끝에서 `pop()`한다. 높이만 저장하고 `heights.index(top)`으로 위치를 되찾으면 매번 선형 탐색이 생긴다. 처음부터 인덱스를 저장하면 높이 확인과 답 기록을 모두 O(1)에 할 수 있다.

## 블로그 판단

단조 스택 개념 글 후보. “오른쪽에서 왼쪽으로 읽을 때, pop한 순간 어떻게 가장 가까운 탑임을 알까?”를 중심으로 위 네 탑의 대기 상태를 그림으로 보여줄 수 있다.
